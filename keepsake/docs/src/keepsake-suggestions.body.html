How to read this

A running list of ideas, refinements, and deviations from Design Bible v3 that came up while building the 2.5D prototype. Items marked acted were small, safe, or privacy/security-related and were applied during the build (also in the Work Log). Items marked proposed await your decision — nothing here has changed the product's direction on its own.

Acted on (small / safe / privacy)

acted Persist photographs locally

The Bible (§3) says the current prototype keeps images in memory and lets them disappear on refresh. For a testable prototype that felt wrong, so books (including photos, as downscaled data URLs) now persist in IndexedDB. Trivially reversible if you want the "ephemeral" behaviour back.

acted privacy Local visibility gating

Private books and the archive are hidden under visitor "View as" modes, and the book becomes read-only for visitors. This is a client-side preview only and is not real security — real enforcement must be server-side (§17). Called out clearly in the UI and Work Log so it is never mistaken for protection.

acted Downscale uploads

Uploaded images are resized to ≤1400px before storage to protect browser memory and IndexedDB quota (a risk noted in §6/§22).

acted Accessibility & small UX polish

Added name/aria-label to all form fields; a Music volume control; visitors see their own pending note. Follow-up pass: skip links, a <main> landmark, named icon buttons, object focus rings, Tab-trapped dialogs that restore focus, a live spread counter, and tour copy exposed in full to assistive tech (the typewriter is visual-only). A real-device VoiceOver/TalkBack pass is still worth doing later (§23).

Proposed (your call)

proposed Room art: painted 2.5D first, toon-3D later (and only if we miss it)

The room is still CSS gradients, Lucide icons, and a few textures. It holds as a prototype, but it is not yet the Little Big Planet / Sly Cooper / Edith Finch diorama the Bible asked for. The Messenger tour borrowed layout from messenger.abeto.co, not its cel-shaded WebGL look. Here is the art brief I would actually commission.

Recommendation

Stay 2.5D. Commission a set of painted, cut-out parallax plates and drop them into the existing depth rig. Do not rewrite the room in Three.js to chase Messenger's toon shader. A full 3D scene is a different product: heavier bundle, new camera language, and it fights the scrapbook-on-a-desk metaphor. Bible §8 already picked 2.5D for this reason.

What I want the room to look like

  • Little Big Planet — objects feel sewn, stuffed, or paper-cut. Soft rim light. A slight “pop” when you hover (we already do this; the art should invite it).
  • Sly Cooper — inked silhouettes, limited palette, storybook noir. Edges read from across the room. Night should go indigo + amber, not grey.
  • Edith Finch — a lived-in house, slightly melancholy, dust in the beam, nothing sterile. Clutter that looks placed by a person, not a UI kit.

Palette already in the prototype: cocoa leather #4a3224, cream paper #f3e9d8, seal red #b55245, dusk mauve, night indigo. New art should lock to those, not invent a second brand.

Deliverables (phase 1 — illustrated plates)

Ask an illustrator for layered PNGs/WebPs with transparent cut-outs, authored at ~2× the scene size so they survive the existing pointer parallax:

  1. Far sky — four plates: day, dusk, night, plus a weather overlay (rain streaks / snow) we can tint. The window already frames this.
  2. Back wall — plaster + picture rail + window casing. Warm, slightly stained. No UI chrome painted in.
  3. Mid furniture — bookshelf (empty bays; we keep drawing spines in CSS so book count stays live), framed timeline, cork map. These must match today's hotspot boxes in lib/hotspots.ts.
  4. Desk + cabinet + CRT — wood grain, a lamp, the kettle, a tea ring already in the wood. The open book stays a live HTML cover (leather + title), not painted shut.
  5. Foreground clutter — a few optional bits (pressed flower, ribbon, letter, loose photo) that the curator can show/hide. Same silhouette language as the mid layer.
  6. Season washes — four multiply overlays (spring green, summer gold, autumn rust, winter blue) rather than four full rooms.

Technical constraints for the brief: 16:9 safe area; keep interactive objects inside the current percentage hitboxes; no baked-in text (we set titles in type); no photoreal PBR; export as premultiplied WebP, max ~400 KB per plate.

What I do not want (yet)

  • A free-orbit 3D camera. The room is a tableau. Parallax is a glance, not a fly-through.
  • A full Three.js rewrite of every object. That would freeze the scrapbook, notes, and curator into a 3D engine we do not need.
  • Messenger's cool grey cel-shade as the house style. Keep cream, ink, and wood. If we ever toon-shade something, the outline colour should be cocoa, not black comic-ink.
  • AI texture dumps or stock isometric rooms. The point is one hand. Same illustrator for every plate.

Optional later: one toon-3D hero, not a 3D house

If painted plates still feel flat after we live with them, the honest Messenger-like experiment is a single WebGL accent — probably the open book, or the window glass — sitting in the 2.5D scene:

  • Toon/cel: a 3–4 stop ramp (MeshToonMaterial or a tiny custom shader), not a realistic light model.
  • Ink outline via an inverted-hull or fullscreen Sobel; stroke in #2c2418, 1–2px.
  • Paper/leather/wood as painted textures, not scanned PBR sets.
  • Camera locked; only a few degrees of parallax, matching the CSS layers.
  • Reduced-motion: freeze the mesh and show the still plate.

That is a spike, not a rewrite. If it does not obviously beat the painted book, throw it away. I would not start there.

Commission shape

One illustrator (or a very small studio), two rounds: greyscale layups against a screenshot of the current room, then colour. Style frames: a LBP sack-person living room, a Sly Cooper hideout interior, Edith Finch's kitchen at dusk. Payment for plates + a year of seasonal variants. We keep hotspot code, tour, and curator as-is.

acted Music: ambient pad + Spotify account login

The CRT is now a provider adapter (§13): an offline generative Web-Audio pad by default, plus a "Connect Spotify" login via browser-safe OAuth PKCE (no client secret). Once connected it can browse your playlists and set one per book; an embedded player handles playback. Needs your input to go live: the Client ID can come from VITE_SPOTIFY_CLIENT_ID / SPOTIFY_CLIENT_ID, or be pasted once in the CRT panel (stored only in this browser). Register the exact Redirect URI shown in the panel. The Client Secret is not used and must never be prefixed with VITE_. Full in-app playback control (vs. the embed/previews) requires Spotify Premium (Web Playback SDK) — a natural next step once credentials exist. Licensed offline lo-fi tracks remain a later option per the Bible.

proposed Export: browser print now, print pipeline later

Export uses the browser's Print / Save-as-PDF. A production path (§25) needs a server PDF renderer with bleed, trim, safe zones, and low-resolution warnings before any print-on-demand vendor.

acted Achievements event ledger

Reworked to match §12: a pure rules engine derives completion from state (idempotent, reproducible grants), each unlock is stamped with a completion time, and a "seen" flag separates completion from reward presentation. Added a few more achievements (storyteller, decorator, collector). Next step is persisting a fuller immutable action ledger once a backend exists.

acted Curated-RNG opportunity queue + expanded catalogue

Replaced the single teaser with a real queue (§20): candidates carry eligibility + priority + cooldown; a curator selects at most one per session and records a persisted receipt so cooldowns hold across sessions. The welcome candidate starts the guided room tour until progress.completedTour is set. The catalogue is now sixteen kinds: welcome, reward, empty-page, whisper, photo-out, ajar-book, bookmark, guest-wave, map-glint, night-moth, pressed-flower, season-note, letter, window-draft, kettle, tea-ring. Quiet events (priority < 25) have a 35% chance of presenting nothing, so the room can stay still. Force one in QA with ?event=<kind>.

acted Messenger-style first-visit dialogue

You asked to borrow the bottom-of-scene text-bubble layout from messenger.abeto.co for a first-login walkthrough. Implemented as a paper/ink dialogue (name plate overlapping top-left, offset block shadow, square next control overlapping bottom-right) with a spotlight that follows each room object. This is a deviation from Bible §21 “discovery over instruction” — taken because you asked for it, and kept skippable / house-voiced so it can still be ignored. The cel-shaded 3D look of Messenger itself (toon shading, ink outlines, WebGL scene) is not copied here; that remains the proposed illustrated-parallax upgrade above.

proposed Stickers & craft assets

Stickers are emoji glyphs for now. Replace with licensed SVG/WebP sticker packs and scrapbook styles (§11), keeping the same transformable-element model already in place.

proposed Map stays abstract / manual

The atlas is an illustrated, non-geocoded map; pins are placed manually. This actually matches the Bible's privacy stance (approximate/manual by default, §16) — I'd keep it and make exact coordinates strictly opt-in if geocoding is ever added.

proposed Single IndexedDB record

For prototype simplicity all state is one record. Production should split per entity and move to a server (Postgres per §4) — expected, not a concern yet.
